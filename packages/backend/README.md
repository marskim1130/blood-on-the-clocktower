# Backend 部署 [Backend Deployment]

## 配置

- `CLOCKTOWER_CREDENTIAL_KEY`：所有生产启动模式必需，至少 32 字节，必须跨重启稳定；当前不支持轮换或恢复。
- `CLOCKTOWER_REDIS_URL`：启用 Redis 每房间持久化。
- `CLOCKTOWER_REDIS_KEY`：Redis 命名空间前缀，生成 `<prefix>:rooms` 与 `<prefix>:room:<roomId>`。
- `CLOCKTOWER_SNAPSHOT_PATH`：文件持久化目录，每房间一个 `<roomId>.json`；若指向旧普通文件则启动失败。

Redis 优先于文件配置；两者均未设置时使用内存存储，数据不跨重启。当前只支持单活动后端实例 [Single Active Backend Instance]。

## 启动

```powershell
$env:CLOCKTOWER_CREDENTIAL_KEY='replace-with-a-persistent-secret-of-at-least-32-bytes'
go run ./cmd/server
```

`GET /health` 正常返回 `200`；检测到房间修订 CAS 冲突后返回 `503`。旧全局 Snapshot 不自动迁移，升级前应保留原存储用于整体回滚。

## 说书人日志与撤销重做

说书人独享本局最近 100 条操作记录和最近 30 步游戏状态撤销/重做。历史与当前游戏快照在同一个 Room Record 中提交；存储失败不会发布撤销结果，也不会改变成员凭据或消耗客户端序列。新游戏状态操作会清空重做分支。加入、离开、更换说书人、调整座次或房间设置会清空可撤销边界，避免恢复旧成员名单；同房重赛清空上一局历史。

跨阶段撤销/重做必须显式确认 `confirmPhaseChange`。已展示的角色、夜间信息、投票和公开魔典无法从玩家记忆中收回，撤销仅恢复应用状态。恢复投票计时器时默认暂停，保留快照时的剩余时长，由说书人手动继续。

## 七天不活跃清理

服务器启动后扫描一次，此后每小时扫描一次。房间创建、首次加入以及成功持久化的成员/游戏命令更新 `lastActiveAt`；失败命令、幂等重试、连接保持、重连与只读查询不续期。因此，即使设备仍在线，连续超过七天没有成功写入的房间仍会被清理。恰好七天时保留，超过七天才删除。

旧记录没有活动时间戳时，首次扫描先用 CAS 持久化本次扫描时间并增加房间修订号，给予完整七天宽限；重启后沿用已保存时间，不会立即误删。迁移失败保留原记录并在后续扫描重试。删除与房间命令共用锁，只有存储 CAS 删除成功后才撤销房间、创建请求别名和在线连接；删除失败仍保留房间与身份凭据。CAS 冲突会令健康检查失败，需排查是否同时启动了多个后端。
